# 代码生成模板（templates/codegen）

> 里程碑：M6（PRD-006）｜ 渲染引擎与命令行见 `packages/cli/src/gen/`

本目录是 `fw gen crud` 的**内置模板库**。执行生成时，渲染层按「项目级同名模板优先 → 框架内置模板兜底」的顺序定位文件（`packages/cli/src/gen/templates.ts` 的 `resolveTemplate`）。

## 1. 目录结构

```
templates/codegen/
├── backend/                  # 后端产物（apps/<app>/src/modules/<model>/）
│   ├── entity.ts.tpl         #   实体接口（含 BaseEntity 通用字段）
│   ├── repository.ts.tpl     #   数据访问（继承 @fw/db 的 PrismaRepository）
│   ├── dto.ts.tpl            #   新建 / 更新 / 查询 DTO
│   ├── service.ts.tpl        #   业务服务（分页 / 详情 / 创建 / 更新 / 软删）
│   ├── controller.ts.tpl     #   REST 端点（/api/v1/<模型复数>）
│   └── module.ts.tpl         #   NestJS 模块定义
├── frontend/                 # 前端产物（apps/<web>/src/{api,views}/<model>/）
│   ├── api.ts.tpl            #   请求封装 + 列表项 / 查询 / 输入类型
│   ├── index.vue.tpl         #   列表页（基于 <CrudTable> 配置）
│   └── form.vue.tpl          #   新建 / 编辑弹窗（独立组件）
└── seed/
    └── permissions.ts.tpl    # 权限点与菜单 seed（4 权限点 + 菜单，幂等 upsert）
```

一个模型（`fw gen crud <model>`）默认生成 **10 个文件**：后端 6 + 前端 3 + seed 1。

## 2. 模板语法

轻量引擎（`packages/cli/src/gen/template-engine.ts`），只支持三种标签：

| 语法 | 说明 |
|---|---|
| `{{变量路径}}` | 取值并原样输出（值为 `undefined`/`null` 时输出空串，不报错） |
| `{{#if 变量}}...{{else}}...{{/if}}` | 真值判断（空数组 / 空串 / `0` / `false` 走 `else`） |
| `{{#each 列表}}...{{/each}}` | 遍历；循环体内用 `{{this}}` 取当前项，`{{this.字段}}` 取对象字段，`{{@index}}` 取下标 |
| `{{#if 变量}}` 中的 `../字段` | 循环体内访问外层数据（如 `{{../model.name}}`） |

> 转义说明：Vue 模板里的 `{{ }}` 会被引擎当成变量标签。需要输出字面量花括号时，用 `{{ '{' }}` / `{{ '}' }}` 拼出来（如 `#{{ '{' }}id{{ '}' }}`）。渲染完成后引擎会压缩 3+ 连续空行为 2，避免控制标签独占行留下大片空行。

## 3. 可用变量

变量由 `packages/cli/src/gen/render.ts` 的 `buildTemplateData` 组装，所有模板共享同一份数据：

**模型（`model`）**

| 变量 | 示例（模型 `OrderItem`） | 说明 |
|---|---|---|
| `model.name` | `OrderItem` | PascalCase 模型名 |
| `model.camel` | `orderItem` | camelCase（变量前缀） |
| `model.kebab` | `order-item` | kebab-case（文件名 / 目录 / 路由段） |
| `model.pluralKebab` | `order-items` | 复数 kebab（REST 路径） |
| `model.routePath` | `/order-items` | 前端路由路径 |
| `model.apiPath` | `/api/v1/order-items` | 接口前缀 |
| `model.comment` | `订单明细` | 模型文档注释（无注释时回落模型名） |
| `model.permissionPrefix` | `order-item` | 权限点前缀（`order-item:read`） |
| `model.constName` | `ORDER_ITEM` | 常量名（`PERM.ORDER_ITEM_READ`） |

**字段分组（`FieldMeta[]`，逐项可用 `name`/`label`/`tsType`/`control`/`required`/`optional`/`isEnum`/`isForeignKey`/`dictCode`/`maxLength` 等）**

| 变量 | 内容 |
|---|---|
| `fields` | 全部字段（含 BaseEntity 通用字段） |
| `entityFields` | 实体字段（排除 `id`/`createdAt`/`updatedAt`/`deletedAt`/`createdBy`/`updatedBy`） |
| `createFields` | 新建输入字段（实体字段再去主键） |
| `formFields` | 表单字段（同 `createFields`） |
| `listFields` | 列表列字段（按映射 `listable`） |
| `searchFields` | 查询条件字段（按映射 `searchable`） |
| `uniqueFields` | 唯一键字段（生成 Repository 便捷查询方法） |

**预渲染片段（直接嵌入，勿二次加工）**

| 变量 | 说明 |
|---|---|
| `columnsCode` | `<CrudTable>` 的 `columns` 配置数组源码 |
| `searchCode` | `searchForm` 配置数组源码 |
| `formCode` | `formFields` 配置数组源码（含校验规则与外键 TODO） |
| `listItemFieldsCode` | 列表项接口的字段声明源码 |
| `uniqueMethodsCode` | Repository 唯一键便捷方法源码 |
| `keywordField` | 首选关键字查询字段名（无则空串） |
| `searchableSummary` | 可搜索字段中文摘要（列表页副标题提示） |

**全局**

| 变量 | 说明 |
|---|---|
| `author` | 署名（`git config user.name`，缺失时回退 `donttemo` 并告警） |
| `created` | 创建日期 `YYYY-MM-DD` |
| `since` | 框架版本（当前 `v0.1.0`） |
| `projectRoot` | 项目根绝对路径 |
| 自定义变量 | `codegen.config.json` 的 `vars` 会平铺到顶层，按需引用 |

## 4. 项目级定制

### 4.1 覆盖单个模板

在**项目根**（不是 `apps/` 下）创建同名路径的模板文件即可，渲染时自动优先取用：

```
my-project/
└── templates/codegen/backend/service.ts.tpl   # 覆盖内置的同名模板
```

其余未覆盖的模板仍走框架内置。适合统一团队风格（如换注释头、改基类、加统一埋点）。

### 4.2 自定义变量

项目根的 `codegen.config.json`：

```json
{
  "vars": {
    "teamName": "交易中台",
    "baseClass": "TeamRepository"
  }
}
```

模板中用 `{{teamName}}` / `{{baseClass}}` 引用。

### 4.3 类型映射覆盖

同一文件的 `typeOverrides` 按 Prisma 类型名覆盖整行映射（影响 TS 类型 / 控件 / 可列表 / 可搜索）：

```json
{
  "typeOverrides": {
    "Decimal": { "tsType": "string", "control": "input", "listable": true, "searchable": true },
    "BigInt": { "tsType": "string", "control": "input", "listable": false }
  }
}
```

> 约定：`decimal` 与 `bigint`（含 `id` / `*_id`）一律映射为 `string`，禁用 `number` 防精度丢失；**未登记的 Prisma 类型直接报错**，不猜测。

## 5. 二次开发边界

- 生成文件头部标注 `@generated by @fw/cli gen crud`，**重跑生成器不会覆盖已存在文件**（除非显式 `--force`）。
- 业务扩展请走**继承 / 钩子**，不要直接改生成文件——否则下次 `--force` 会丢失改动。
- 需要长期生效的改动，改的是**模板**而不是产物：要么在项目根覆盖模板，要么直接改本目录内置模板并提交。
- 生成失败（含模板语法错误、后端 `tsc` 校验失败）时，`writer.ts` 会回滚本次已写入的全部文件，不留半成品（TC-GEN-006）。

## 6. 相关命令

```bash
fw gen crud <model> --dry              # 预览：输出与真实生成完全一致，但不落盘
fw gen crud <model>                    # 生成（已存在文件跳过并提示 --force）
fw gen crud <model> --force            # 覆盖已存在文件
fw gen crud <model> --only=frontend    # 只生成前端三文件（all | backend | frontend | seed）
fw gen crud --all                      # 批量生成 schema 中全部可生成模型
```

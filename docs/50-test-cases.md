# 通用应用框架 · 测试用例

> 版本 v0.1 ｜ 状态：草案 ｜ 关联：[验收标准](./10-acceptance-criteria.md) ｜ [API 文档](./40-api-spec.md) ｜ 更新：2026-10-09
>
> 定位：把验收标准（判「过不过」）落成可执行用例（判「怎么测」）。编号规则 `TC-<模块>-<三位序号>`，每条用例须可自动化或可手工复现，并标注优先级与所属里程碑。

## 1. 测试策略

| 层级 | 占比 | 工具 | 范围 | 运行频率 |
|---|---|---|---|---|
| 单元测试 | ~70% | Vitest / Jest | 纯函数、装饰器、类型映射、适配器逻辑（用 fake 实现） | 每次提交 |
| 集成测试 | ~25% | Supertest + Testcontainers | 接口 + 真实 DB / Redis / MQ | 每次 PR |
| 端到端 | ~5% | Playwright（后台关键流） | 登录 → 权限 → CRUD → 审计 | 每日 / 发布前 |
| 非功能 | — | k6 / autocannon、依赖扫描 | 性能、安全、兼容性 | 每日 / 发布前 |

原则：**能单测的不写集成，能集成的不写 E2E**；E2E 只保留 5 条以内黄金路径。

## 2. 测试环境矩阵

| 场景 | 数据库 | 缓存 | 队列 | 说明 |
|---|---|---|---|---|
| 本地单测 | SQLite（文件/内存） | memory | memory | 秒级反馈，无需容器 |
| CI 集成 | MySQL 8 **且** PostgreSQL 15（并行） | Redis 7 | bullmq | 三库矩阵，任一失败阻断 |
| 演练环境 | 目标库 | 对应驱动 | 对应驱动 | 用于切换 / 演进 / 降级演练 |

## 3. 测试数据约定

- 种子数据 `db:seed`：内置角色（admin/guest）、权限点、菜单、字典、管理员账号。
- 业务数据用工厂函数生成（`makeUser()` / `makeOrder()`），**禁止依赖手工库数据**。
- 用例间隔离：每个用例独立事务回滚，或独立 schema；禁止用例间顺序依赖。
- 随机化：用户名、订单号带随机后缀，避免唯一约束冲突。
- 敏感数据：测试数据不得含真实个人信息；令牌与密码仅用测试常量。

## 14. 易漏用例清单（评审重点）

1. **横向越权**：改 URL 中的资源 ID 访问他人/他租户数据。
2. **前端隐藏即安全**：按钮隐藏但接口未校验。
3. **缓存与事务时序**：回滚后缓存已被删导致脏读。
4. **刷新令牌并发**：多标签页同时刷新被误判重放。
5. **软删除遗漏**：关联查询未带 `deleted_at IS NULL`。
6. **分页边界**：最后一页、空结果、`pageSize` 超限、排序字段不稳定。
7. **降级回切**：Redis 恢复后仍走直查，或恢复瞬间读脏。
8. **时间与时区**：跨时区日期筛选差一天。
9. **金额精度**：浮点导致的分位误差。
10. **生成器覆盖**：重跑覆盖手写业务逻辑。

## 15. 缺陷与回归

- 缺陷分级：P0（阻断，安全/数据丢失/不可用）、P1（主要功能异常）、P2（体验与边界）。
- 每个 P0/P1 缺陷必须补一条回归用例（编号沿用所属模块，后缀 `-R`）。
- 缺陷关闭标准：用例通过 + 根因说明 + 同类问题排查结论。

# PRD-006 · CRUD 代码生成器

> 里程碑：M6 ｜ 状态：已完成（未发版）｜ 优先级：P1 ｜ 依赖：M2、M5 ｜ 负责人：donttemo ｜ 更新：2026-10-13

## 1. 背景与目标

框架本身不能自动让开发变快；真正压缩工期的是「表设计完 → 前后端 CRUD 可运行」这一步。

目标：`fw gen crud <model>` 一条命令，由数据模型生成后端模块（Entity/Repository/DTO/Service/Controller + 迁移脚本 + 权限点 SQL）与前端页面（API 封装 / 列表 / 表单 / 菜单）。

衡量：一张新表到端到端可用 CRUD ≤ 10 分钟（目标 G4）。

## 2. 范围

**做**：模型解析、<u>后端代码生成、前端代码生成、模板可定制、dry-run 预览与安全覆盖策略、菜单与权限点注册、批量生成。</u>

**<u>不做</u>**<u>：业务逻辑生成（复杂校验、状态机需人工编写）、数据库表结构设计（由人完成）、可视化建模界面。</u>

## 3. 用户故事

- 作为开发，我建好表后执行一条命令，得到可直接运行的 CRUD 模块，再手工补充业务规则。
- 作为开发，我把公司自己的代码风格做成自定义模板，生成结果直接符合规范。
- 作为开发，我重跑生成器时不会被覆盖已修改的文件（除非显式 `--force`）。
- 作为架构师，我把生成器模板纳入版本管理，全团队统一产出风格。

## 4. 功能需求（FR）

| 编号    | 需求      | 说明                                                                                                                                                                                           |                                                 |
| ----- | ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| FR-01 | 模型来源    | 支持两种输入：Prisma schema（推荐）与已有数据库表（反向解析）；输出统一的字段元信息（类型、可空、默认值、注释、索引、唯一键）                                                                                                                        |                                                 |
| FR-02 | 后端生成    | 生成 `entity / repository / dto(create/update/query) / service / controller`，全部基于 PRD-002 的 Repository 接口，不生成裸 SQL                                                                             |                                                 |
| FR-03 | 前端生成    | 生成 `api/<model>.ts`、`views/<model>/index.vue`（基于 `<CrudTable>`）、`views/<model>/form.vue`、字段到表单控件的映射（按类型与注释推断）                                                                                |                                                 |
| FR-04 | 权限与菜单   | 生成权限点（`资源:create/read/update/delete`）与菜单插入 SQL/seed 文件，与 PRD-003 RBAC 对齐                                                                                                                     |                                                 |
| FR-05 | 类型映射    | 内置类型映射表（数据库类型 → TS 类型 → 表单控件 → 校验规则），支持项目级覆盖配置                                                                                                                                               |                                                 |
| FR-06 | 模板定制    | 模板用轻量模板引擎（EJS/Handlebars）存放于 `templates/codegen/`，项目可覆盖同名模板；支持自定义变量                                                                                                                          |                                                 |
| FR-07 | 安全写入    | 默认不覆盖已存在文件，输出 diff 预览；`--force` 才覆盖；生成前自动 `git status` 检查（脏工作区告警）                                                                                                                            |                                                 |
| FR-08 | dry-run | `fw gen crud <model> --dry` 只打印将要创建/修改的文件与 diff，不落盘                                                                                                                                          |                                                 |
| FR-09 | 批量与交互   | 支持 `--all`（全表）、\`--only=backend                                                                                                                                                              | frontend`、`--model=a,b\`；无参数时进入交互式选择（多选表、选择生成项） |
| FR-10 | 生成后自检   | 生成结束打印「下一步」清单（跑迁移、重启、访问路径），并对缺字段注释、无索引等给出提示                                                                                                                                                  |                                                 |
| FR-11 | 中文文件头   | 所有生成文件自动写入中文文件头注释块，含 `@file` `@description` `@author`（执行生成者）`@created`（当天 `YYYY-MM-DD`）`@since` 与 `@generated by @fw/cli`；作者取 `git config user.name`（本仓库默认 `donttemo`），未配置时回退默认署名并告警，绝不生成空作者 |                                                 |

## 5. 非功能需求（NFR）

- 单表生成耗时 ≤ 3s；批量 20 表 ≤ 20s。
- 生成代码必须通过 ESLint 与 TypeScript 编译（生成器内置一次校验，失败则回滚本次写入）。
- 生成器自身单测覆盖率 ≥ 80%（重点：类型映射、模板渲染、覆盖策略）。
- 生成代码与手写代码风格一致（同 ESLint/Prettier 规则），不留「机器味」。

## 6. 关键设计

**命令**

```bash
fw gen crud order --dry            # 预览
fw gen crud order                  # 生成前后端
fw gen crud order --only=backend   # 仅后端
fw gen crud --all                  # 全表
```

**字段元信息 → 控件映射（默认）**

| 数据库类型                     | TS 类型        | 前端控件               | 校验                     |
| ------------------------- | ------------ | ------------------ | ---------------------- |
| varchar/char              | string       | 输入框                | 长度上限                   |
| text                      | string       | 文本域                | —                      |
| int（非 ID） / smallint      | number       | 数字框                | 数值范围                   |
| **bigint（`id` / `*_id`）** | **string**   | 只读 / 关联选择          | 存在性校验（禁止 number，防精度丢失） |
| **decimal(p,s)**          | **string**   | 金额框                | 精度校验（字符串传输，禁浮点）        |
| boolean/tinyint(1)        | boolean      | 开关                 | —                      |
| enum                      | 联合字面量        | 下拉（取 `dict_items`） | 枚举值                    |
| datetime/timestamp        | string(Date) | 日期时间选择器            | 时间格式，提交转 UTC ISO 8601  |
| json                      | Record       | JSON 编辑器（只读展示优先）   | JSON 校验                |
| 外键 `xxx_id`               | string       | 关联选择（可配数据源）        | 必填                     |

> 映射表以 [数据字典 1.3](./../30-data-dictionary.md) 为唯一来源，项目级可覆盖；未命中类型直接报错，不猜测。

**目录约定**（生成到 `apps/<app>/modules/<model>/` 与 `web/src/views/<model>/`），保证多项目结构统一。

## 7. 验收标准（AC）

- [x] 新建一张含 8 个字段（含枚举、时间、外键）的表，从执行生成命令到页面可增删改查 ≤ 10 分钟。
      → 以仓库真实 schema 的 `DemoItem` 为载体验证：`fw gen crud demo-item` 一次产出后端 6 + 前端 3 + seed 1 共 10 文件，后端 `tsc` 与前端 `vue-tsc` 零错误。
- [x] 生成的代码零修改即可通过 `pnpm lint && pnpm build`。
      → `apps/example-api` `tsc --noEmit` 通过；`apps/admin-web` `vue-tsc --noEmit` 通过（生成期发现的表单断言问题已在模板层修正为 `as unknown as`，属模板缺陷而非产物手改）。
- [x] 重跑生成器时，已手工修改的文件不被覆盖，并提示 `--force`。
      → `writer.ts` 默认跳过已存在文件并打印 `--force` 提示；单测覆盖（TC-GEN-003）。
- [x] `--dry` 输出与真实生成结果完全一致（除不落盘外）。
      → dry-run 与真实生成共用同一渲染路径（`buildPlan`），仅落盘环节不同；单测覆盖（TC-GEN-004）。
- [x] 生成的权限点写入数据库后，后台角色配置页可见并可勾选。
      → `prisma/seed/<model>.seed.ts` 幂等 upsert 4 个权限点（`<kebab>:create/read/update/delete`）+ 菜单；`prisma/seed.ts` 引用后 `fw db:seed` 落库（TC-GEN-005）。
- [x] 替换一个自定义模板后，生成结果随之改变（模板机制生效）。
      → 项目根 `templates/codegen/<同名>` 优先于内置（`resolveTemplate`）；单测覆盖（TC-GEN-007）。
- [x] 生成失败（如模板语法错误）时不留下半成品文件。
      → `writer.ts` 写前快照 + 失败回滚（含删除本次新建文件与空目录）；单测覆盖（TC-GEN-006）。
- [x] 生成文件均带中文文件头（`中文描述 + @author + @created`），`pnpm run check:headers` 通过；作者统一署名 `donttemo`，未配置 `git user.name` 时回退默认并告警而非生成空作者。
      → 作者解析走 `git config user.name`，缺失回退 `DEFAULT_AUTHOR` 并告警（单测覆盖）；根文件头门禁 221 文件通过。

## 8. 依赖与风险

- 依赖 M2（模型与 Repository 接口）与 M5（`<CrudTable>` 组件与前端目录规范）。
- 风险：生成代码与手写代码冲突（重复生成覆盖业务逻辑）→ 强制 `--force` + diff 预览 + 生成文件头部标注 `@generated` 并建议业务扩展走继承/钩子。
- 风险：类型映射覆盖不全导致生成错误代码 → 映射表可配置，未命中类型时报错而非猜测。

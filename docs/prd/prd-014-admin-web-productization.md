# PRD-014 · Admin Web 产品化与 SaaS 运营体验升级

> 里程碑：M14｜ 状态：**草案**（2026-10-19）｜ 优先级：P1 ｜ 依赖：M13 已交付能力（重点：`@fw/saas` 领域服务、SaaS 运营九端点、admin-web 四页、M12 审计/错误契约、M8 `@fw/tenant`）｜ 负责人：donttemo ｜ 更新：2026-10-19
>
> 来源：2026-10-19 前端产品化外部评审 + 本仓源码逐条核实（证据以文件行号登记于 §1.2，与核实当日记录一致）。
>
> 与既有 PRD / ADR 的关系：
> - **PRD-013（M13）FR-13-15/16 交付了运营 API 最小集与四页**，本 PRD 是其产品化续篇，不回滚、不推翻任何 M13 语义。
> - **ADR-0031（生命周期状态机）、ADR-0025/0026（错误与审计契约）、ADR-0027（运维边界）继续成立**；本 PRD 新端点全部沿 M12/M13 契约，不新造体系。
> - PRD-011 非目标 **NG11-1（不接支付）** 延续。

## 1. 背景与目标

### 1.1 现状基线

M13 交付后：后端已具备套餐/订阅/配额/用量/生命周期完整领域模型与九个运营端点；admin-web 具备全局布局、动态路由、RBAC、暗色主题、通用 CRUD 组件与 SaaS 四页（套餐/订阅/生命周期/用量）。CI 全绿（44e5341），真机 v0.7.0 验收通过。

但四页整体是「功能验证型」：交互以单租户手输 ID + 表格 + 消息提示为主，且存在若干**操作正确性缺陷**（非外观问题）。下一阶段的完成标准不再是「增加了几个 Vue 页面」，而是「运营人员能否完整、高效、安全地完成一项业务」。

### 1.2 结构性缺口（2026-10-19 源码核实，含证据）

| # | 缺口 | 现状与证据 | 影响 |
|---|---|---|---|
| U-14-1 | **操作原因未真正提交** | `lifecycle/index.vue:51` `ElMessageBox.prompt()` 返回值未接收，`:56` 调用未传 `reason`；`subscriptions/index.vue:65/70` 取消订阅同样丢失。而 API 层 `api/saas.ts:29/64` 与后端控制器**均已支持** `reason` 参数 | 运营人员以为已填写原因，后台与审计实际收不到；操作不可追溯 |
| U-14-2 | **写按钮无权限渲染** | `v-permission` 指令已存在（`directives/permission.ts`）且 system 各页在用，SaaS 四页零使用；生命周期六按钮仅 `:disabled="!tenantId"`；订阅页头注释声称「按权限码渲染」与实现不符 | 只读角色看到可点按钮，点击后才收到 403；注释误导后续维护 |
| U-14-3 | **生命周期状态推导不可靠** | `currentStatus` 取迁移日志末条（`lifecycle/index.vue:41`），无日志时不显示且六按钮全可点；控制器已有 `statusOf()`（直读 `store.findTenantStatus`）但未暴露端点 | 无日志租户可发起非法迁移（后端 4030 兜底，但交互不成立）；页面不显示当前状态 |
| U-14-4 | **套餐领域能力未开放** | `PlanService.createPlan/publishVersion` 已存在，控制器无对应 POST 端点；`plans/index.vue` 头注释写明「发布走脚本/后续批次端点」（M13 已知留白） | 套餐创建与版本发布只能走脚本；前端无法做成完整运营流 |
| U-14-5 | **订阅无列表/历史视图** | 仅有单租户「查当前订阅」；手输租户 ID、手填套餐编码；无全局列表、筛选、历史 | 不适合日常运营；跨页操作需反复记忆/输入租户 ID |
| U-14-6 | **用量是查询面板不是看板** | 仅单租户单指标当前窗口（rollup 重算）；无趋势/明细/跨租户风险端点；切换租户后 `usage.value` 残留上一租户数据（`usage/index.vue:53` 仅在 `usageKey` 为空时刷新） | 看不出业务趋势；数据残留可能误导判断 |

### 1.3 产品目标

| # | 目标 | 衡量口径 |
|---|---|---|
| G14-1 | **可追溯**：每个写操作的原因端到端落库，审计完整 | 生命周期/取消订阅的原因可 DB 断言；审计事件含 after 快照 |
| G14-2 | **能力闭环**：前端展示的每个操作都有真实 API 支撑；已具备的领域能力不滞留服务层 | 套餐创建/发布走管理端完成；无任何「看起来能点、实际不可提交」的按钮 |
| G14-3 | **体验一致**：统一四态（加载/空/错误/无权限）、统一危险操作确认、租户上下文跨页携带 | SaaS 各页交互规范同构；租户选择器替代手输 ID |
| G14-4 | **运营首页**：登录即见待处理事项 | 工作台展示到期/冻结/接近配额租户与最近变更 |

### 1.4 非目标（不做）

- 不推翻现有 Vue 3 + Element Plus 架构，不引入新 UI 框架/组件库/可视化大屏方案。
- 不接支付、账单（NG11-1 延续；FR-13-13 账单基础不在本 PRD 范围）。
- **订阅升级/降级/续期默认不进 M14**：属于新领域能力（订阅状态机扩展 + ADR-0031 衔接），见 OQ-14-2；前端不得先造入口。
- 不做租户侧（tenant-facing）自助控制台，仅平台运营面（`ops:saas:*`）。
- 不新增权限码（沿用 `ops:saas:read/write`），避免存量环境 reseed；如评审要求新增须登记 reseed 步骤。

### 2.2 依赖顺序

**B1 独立先行 → B2 后端先行 → B3 前端跟随 → B4 收尾**。硬规则：每个页面/功能按「需求与接口契约 → 后端 API 与领域逻辑 → 前端实现与页面测试 → CI/浏览器 E2E/实机验收」四步闭环交付，**禁止前端先造后端不支持的交互**（M13 的套餐发布留白注释即是正确先例）。领域规则未冻结前不铺页面。

## 3. 目标用户与使用场景

| 角色 | 核心诉求 |
|---|---|
| 平台运营人员 | 不碰数据库完成套餐发布、订阅管理、租户冻结/恢复；从首页直接发现到期/超限/冻结租户 |
| 平台管理员（只读审计视角） | 能看不能改：看不到写按钮，直调 API 被 403 |
| 框架开发者 | 四页是可复用的「运营页范式」（四态/确认/权限渲染同构），新运营页照抄骨架 |

关键场景：
1. **发布新版本**：运营在套餐页选套餐 → 复制上一版本为起点 → 修改配额 → 预览差异 → 确认发布 → 新订阅绑定新版本，历史订阅快照不变。
2. **处理到期租户**：首页提示 3 天内到期 → 点击进入订阅详情 → 续期入口（若 OQ-14-2 升档）或人工联系记录原因。
3. **冻结违规租户**：订阅/租户页进入生命周期 → 页面显示真实状态与合法动作 → 冻结（原因必填）→ 状态与时间线即时刷新。
4. **只读巡检**：审计角色打开四页，无任何写按钮，查询/导出正常。

## 6. 关键设计（摘要）

1. **能力对齐原则**：每个前端按钮必须映射一个已存在的端点；领域能力未开放前，页面只读并明确标注「发布走脚本/后续批次」（M13 先例）。
2. **`ConfirmWithReason` 是唯一原因收集入口**：杜绝 prompt 返回值丢失类缺陷再次出现；必填策略见 OQ-14-5。
3. **租户上下文**：`TenantPicker` + 路由 query 携带 tenantId，跨页跳转（租户 → 订阅 → 生命周期 → 用量）不丢上下文、可分享可回退（OQ-14-4 定案）。
   实现口径（2026-10-20 收口）：三页统一走 `composables/useTenantQuery` —— 首屏读 `?tenantId=` 初始化选择器并**自动取数**，参数缺失/非法（空串、空白、非字符串）视为无租户**零请求**，浏览器前进/后退在同实例内跟随；URL 只作**输入**（页面内换租户不回写），因为 `layout/AppMain.vue` 的 keep-alive 以 `route.fullPath` 为 key，回写会让在途实例与新实例各取一次数、且旧实例缓存被新租户数据污染（违反 FR-14-04 数据隔离）。
4. **发布差异预览**：默认前端 diff（上一版本配额 vs 表单数据均已具备），后端不做 diff 端点（OQ-14-1）。
5. **mock 同构交付**：每端点沿 M13 范式 mock 同步 + smoke-mock 用例；「范围固定」断言（热更键数/CSV 表头/码表）扩键时三处同步（M13 CI 教训）。
6. **菜单/路由回归**：新增页面入真实菜单结构 + 浏览器操作回归清单（v0.7.0 SaaS 四页 404 教训，docs/90 §4）；1Panel 站点 no-cache 头已根治，不回退。

# 通用应用框架 · 项目愿景与范围（1 页）

> 版本 v0.1 ｜ 状态：草案 ｜ 负责人：待定 ｜ 更新日期：2026-10-09

## 愿景（一句话）

做一套「框架之上的框架」：团队用它**在 1 天内**搭出任意业务系统的可运行骨架（登录 + 权限 + 一个 CRUD），3 天内交付可使用的管理模块——小到内部工具站，大到多租户 SaaS——规模升级时**不重写业务代码**。

## 问题陈述

- 每个新项目重复造轮子：登录、权限、缓存、日志、错误处理各做一遍，2–4 周才出第一个 CRUD。
- 框架选型随规模摇摆：小系统嫌重、大系统嫌散，中途换栈代价极高。
- 数据库 / 缓存 / 鉴权与业务代码深度耦合，换 MySQL→PostgreSQL 或引入 Redis 就要大改。

## 目标（Goals）

| 编号 | 目标 | 衡量方式 |
|---|---|---|
| G1 | 新系统 1 天内跑通骨架（登录 + 权限 + 一个 CRUD） | 模板 + CLI，`pnpm create app` 起算 ≤ 1 天 |
| G2 | 业务代码零改动的规模演进（小→中→大） | 仅改 `.env` 与部署形态，业务代码 diff = 0 |
| G3 | 基础设施可替换（DB / 缓存 / 鉴权 / 队列） | 每种能力 ≥ 2 种实现，配置切换，CI 有测试矩阵 |
| G4 | 一个 CRUD 模块 ≤ 10 分钟 | 代码生成器端到端产出前后端可运行代码 |
| G5 | 默认安全与可观测 | 鉴权、审计、限流、日志、健康检查默认开启，不靠自觉 |

## 非目标（Non-Goals）

| 编号 | 非目标 | 说明 |
|---|---|---|
| NG1 | 不做具体业务系统 | 只提供骨架与可插拔模块，业务由各项目自行实现 |
| NG2 | 不自研数据库 / MQ / 对象存储 | 只做适配层，不重复造基础设施 |
| NG3 | 不追求极限性能 | 开发效率与可维护性优先，性能靠横向扩展与缓存 |
| NG4 | 不做低代码 / 零代码平台 | 产出的是可读可改的源码，不是运行时解释的元数据 |
| NG5 | 不覆盖前端全部场景 | 只提供后台管理模板与 CRUD 组件，不做营销页 / 大屏 |
| NG6 | 首版不做国际化 / 多语言 | 时间仍统一 UTC 存储、展示层转本地时区；多语言文案留待后续 |
| NG7 | 不做公有云托管运营 | 只交付可自托管的框架与部署模板 |

## 边界（Boundaries）

**在范围内**

- 框架核心包：`core`(配置/启动)、`orm`、`cache`、`auth`、`queue`、`logger`
- 每种能力的**适配层**：统一接口 + 多实现 + 配置切换
- 项目模板：`admin`（管理后台）、`api`（纯接口服务）、`cms`（内容 / 门户）
- CRUD 代码生成器与 CLI 工具
- 部署模板：单机 Docker → docker-compose → K8s
- 文档：架构说明、PRD、模块使用指南、迁移手册

**在范围外**

- 具体业务领域逻辑（订单、支付、物流等）——由业务项目自行实现
- 基础设施本身的运维调优（DB 参数、Redis 集群运维）
- 移动端原生开发与小程序前端（仅提供后端对接能力）

**规模边界（分级承诺）**

| 规模 | 定义 | 承诺 |
|---|---|---|
| 小 | 单机、日活 < 1k、单库 | SQLite / MySQL + 内存缓存，1 台 1C2G 可跑 |
| 中 | 多实例、日活 1k–10w、主从库 | MySQL / PG + Redis + 队列，compose 编排 |
| 大 | 微服务、日活 > 10w、多租户 | 服务拆分 + Redis Cluster + Kafka + K8s |

## 技术基线

TypeScript + NestJS + Prisma + cache-manager/ioredis + Passport + Vue3/Element Plus + pnpm monorepo。
其它语言栈（Spring Boot / Go / Django）仅作备选，**不在首版范围**。

## 成功指标（上线 3 个月复盘）

1. 新项目 0 → 可交付 CRUD ≤ 3 天（原 2–4 周）
2. 至少 2 个真实项目使用同一框架，且分属不同规模档位
3. 演练一次数据库切换：MySQL → PostgreSQL，业务代码改动为 0
4. 框架包单测覆盖率 ≥ 70%，其中 `auth` / `cache` / `orm` ≥ 85%

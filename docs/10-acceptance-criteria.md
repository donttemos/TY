# 通用应用框架 · 验收标准

> 版本 v0.1 ｜ 状态：**M1–M4 已验收（v0.1.0，2026-10-13）** ｜ 适用范围：M1–M8 全部交付 ｜ 更新：2026-10-13
>
> 本文件是**全局验收总纲**：各 PRD 的 AC 是「点」，本文件定义「线与面」——完成定义、里程碑门禁、非功能基线、关键演练与验收流程。三者冲突时以本文件为准。

## 1. 验收分层

| 层级 | 对象 | 判定者 | 依据 |
|---|---|---|---|
| L1 完成定义（DoD） | 每个需求 / PR | 开发者 + 评审人 | 第 2 节 |
| L2 里程碑门禁 | 每个 PRD（M1–M8） | 负责人 + 架构评审 | 第 3 节 + 对应 PRD 的 AC |
| L3 全局发布门禁 | 版本发布 / 交付 | 项目负责人 | 第 4–6 节 |

## 2. 完成定义（Definition of Done）

一个需求或 PR 只有同时满足以下全部条目才算「完成」，缺一项不得合并：

- [ ] **功能**：对应 PRD 中该 FR 的行为与文案一致，含边界与异常分支。
- [ ] **测试**：新增单测；涉及接口的补集成测试；关键路径有端到端用例。
- [ ] **质量**：`pnpm lint` 与 `pnpm build` 零错误；无新增 `any`；无 TODO 遗留（或已建 issue）。
- [ ] **注释**：注释为简体中文；新增/修改文件有文件头且 `@author`、`@created` 完整；`TODO` 带责任人与日期；`pnpm run check:headers` 通过（规范见 [§1.6](./70-engineering-standards.md)）。
- [ ] **可观测**：日志带 traceId；新能力接入指标（第 5 节指标清单）。
- [ ] **安全**：无硬编码密钥/口令；输入校验完备；涉及权限的补越权用例。
- [ ] **文档**：使用方式写入对应文档；配置项写入 `.env.example` 与配置说明。
- [ ] **兼容**：未破坏既有接口；若破坏，已提供迁移步骤并通知下游。
- [ ] **AC 勾选**：该需求关联的验收项在 PRD 中逐条勾选并附验证方式（命令 / 用例 / 截图）。

## 3. 里程碑门禁（逐门通过才进入下一里程碑）

每个里程碑必须：**该 PRD 全部 AC 通过** + **下列门禁项通过**。

| 里程碑 | PRD | 关键门禁（摘要，完整 AC 见各 PRD） |
|---|---|---|
| M1 核心骨架 | [001](./prd/prd-001-core-skeleton.md) | 30 分钟内跑通模板项目 `/health`；缺配置启动即明确报错；响应与日志 traceId 一致；异常不裸抛 500；`SIGTERM` 在途请求处理完再退出；密码类字段日志脱敏 |
| M2 数据库抽象 | [002](./prd/prd-002-database-abstraction.md) | **三库集成测试全绿**；切换演练业务代码 diff = 0；原生 SQL 未标注即 CI 失败；慢查询告警带 traceId；`db:rollback` 可用 |
| M3 鉴权与权限 | [003](./prd/prd-003-auth-rbac.md) | 越权/重放/篡改/爆破用例全绿；refresh 轮换且旧令牌即时失效；权限变更即时生效；审计可还原字段前后值；多策略同服务共存 |
| M4 缓存层 | [004](./prd/prd-004-cache-layer.md) | memory 零依赖跑通；改配置切 redis 业务 diff = 0；并发 100 打热点 key 回源 1 次；Redis 宕机降级可用；分布式锁生效 |
| M5 后台模板 | [005](./prd/prd-005-admin-template.md) | 未授权路由直接输 URL 被拦截；按钮级权限生效；新列表页 ≤ 80 行；token 过期无感刷新；构建产物纯静态可 Nginx 托管；页面布局 / 四态（加载·空·错误·无权限）/ 交互与 [原型与 UI](./25-ui-prototype.md) 一致 |
| M6 代码生成器 | [006](./prd/prd-006-code-generator.md) | 新表到可用 CRUD ≤ 10 分钟；生成代码 lint+build 通过；不覆盖已改文件（除非 `--force`）；`--dry` 与真实结果一致 |
| M7 队列与调度 | [007](./prd/prd-007-queue-scheduler.md) | memory/bullmq 行为一致；集群下定时任务只跑一次；重试退避 + 死信可重放；重启不丢任务 |
| M8 多租户与规模化 | [008](./prd/prd-008-multitenancy-scale.md) | transport 切换不改调用方代码；**跨租户越权用例全绿**；缺租户上下文 fail-closed；traceId 跨服务贯通；Helm 部署探针/滚动更新/HPA 生效 |

> 门禁判定以实际运行结果为准：**未执行的检查项记 0 分，不得记为通过**。

## 4. 非功能基线

### 4.1 性能基线

| 指标 | 目标 | 测量方式 |
|---|---|---|
| 冷启动（不含 DB 连接） | ≤ 1.5s | 本地 10 次取 P95 |
| 登录接口 | P95 ≤ 300ms | 压测 50 并发 5 分钟 |
| 鉴权守卫单次开销 | ≤ 5ms（缓存后） | 单测基准 |
| 缓存 get（memory） | ≤ 1ms | 单测基准 |
| 缓存 get（redis 同机房） | ≤ 3ms | 单测基准 |
| 单表 100 万行分页查询 | P95 ≤ 200ms（带索引） | 压测脚本 |
| 单表 CRUD 生成耗时 | ≤ 3s（批量 20 表 ≤ 20s） | CLI 计时 |
| 后台首屏可交互 | ≤ 2s（内网） | Lighthouse |
| 后台打包体积 | gzip ≤ 500KB | 构建产物统计 |
| SQLite 单测套件 | ≤ 60s | CI 计时 |

### 4.2 安全基线（缺一即不予验收）

- [ ] 越权：A 用户/租户无法读取或修改 B 的数据（横向越权用例全绿）
- [ ] 重放：refresh token 复用被识别并踢下线；请求重放无副作用
- [ ] 篡改：令牌签名被篡改一律拒绝；前端隐藏权限不可绕过（服务端二次校验）
- [ ] 爆破：连续失败达阈值锁定并告警
- [ ] 注入：SQL 注入 / XSS / 命令注入用例通过；参数一律走绑定与校验
- [ ] 脱敏：密码、令牌、身份证等字段在日志与响应中不可见
- [ ] 密钥：全部来自配置或密钥管理，代码中无硬编码，仓库扫描无命中
- [ ] 传输：生产强制 HTTPS；Cookie 标记 `HttpOnly` / `Secure` / `SameSite`
- [ ] 依赖：依赖漏洞扫描无高危；锁文件纳入版本管理

### 4.3 兼容性与可维护性

- [ ] 运行时：Node 20 / 22 均可运行；pnpm 9+
- [ ] 数据库：MySQL 8、PostgreSQL 15、SQLite 3 三套集成测试通过
- [ ] 缓存：Redis 6 / 7 通过（含哨兵连接串）
- [ ] 浏览器：Chrome / Edge / Firefox 最新两个大版本（后台模板）
- [ ] 覆盖率：框架包整体 ≥ 70%，`auth` / `cache` / `orm` ≥ 85%，`cli`（生成器）≥ 80%，`core` / `config` / `logger` ≥ 80%
- [ ] 模块边界：静态检查禁止跨模块引用内部实现

## 5. 可观测基线

- [ ] `/health`（存活）、`/ready`（依赖就绪，含 DB / Redis 逐项状态）、`/metrics`（命中率、队列积压、慢查询计数）
- [ ] 结构化日志字段固定：`time / level / traceId / spanId / module / msg / ctx`
- [ ] 敏感字段自动脱敏；单条日志 ≤ 8KB 自动截断
- [ ] 慢查询（> 500ms）、缓存慢操作（> 50ms）、降级事件均有告警日志

## 6. 三大关键演练（L3 发布门禁必做）

| 演练 | 操作 | 通过标准 |
|---|---|---|
| 数据库切换 | 示例项目 MySQL → PostgreSQL：改配置 → 迁移 → 种子 → 跑集成测试 | 业务代码 diff = 0，功能全绿，耗时 ≤ 1 小时 |
| 规模演进 | 单体 → 拆出 1 个微服务（transport 切换）+ compose → Helm | 调用方代码不改；链路追踪贯通；滚动更新无中断 |
| 依赖故障降级 | 依次停 Redis、注入 DB 慢查询、制造队列积压 | 接口仍正确返回（降级直查），有告警；恢复后自动回切，无脏数据 |

## 7. 验收流程

1. **自测**：开发者按 DoD 自检，PR 中逐条勾选并附验证证据（命令输出 / 用例名 / 截图）。
2. **交叉评审**：至少 1 名非作者评审，重点看边界、异常、安全与文档一致性。
3. **演示验收**：里程碑结束时对负责人演示门禁项与关键演练，现场跑一遍。
4. **签署**：填写下方验收记录，签署后里程碑状态改为「已验收」。
5. **阻塞处理**：任一 P0 项未通过 → 里程碑不得关闭；P1 未通过可留「条件通过」，须带责任人与闭环时间。

**P0 阻断红线（出现即不予验收）**：越权漏洞、数据丢失或不一致、密钥硬编码、依赖不可用即整体 500（无降级）、AC 未实际执行却标记通过。

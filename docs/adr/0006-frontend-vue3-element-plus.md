# ADR-0006 · 后台前端采用 Vue3 + Element Plus

- 状态：已采纳
- 日期：2026-10-09
- 关联：PRD-005、PRD-006

## 背景

1. 框架提供的前端仅限**管理后台**（列表 + 表单 + 权限菜单），不含营销页与大屏。
2. 需要成熟的表格/表单/权限组件生态，以及可被代码生成器消费的标准组件。
3. 构建产物必须是纯静态资源，可用 Nginx 托管，不依赖 Node 运行时。
4. 团队可能有 React 背景，需要给出第二模板的规划路径。

## 决策

后台模板采用 **Vue3 + Vite + TypeScript + Element Plus + Pinia**，核心抽象为 `<CrudTable>` 组件与 `v-permission` 指令；构建产物为静态资源。React 版本作为**第二模板**在 M5 之后按需求补，不阻塞首版。

## 备选方案

| 方案 | 优点 | 缺点 | 未选原因 |
|---|---|---|---|
| React + Ant Design | 生态大、组件专业 | 体积较大；团队若以 Vue 为主则成本更高 | 作为第二模板待定 |
| Vue3 + Element Plus | 后台组件齐全、体积较小、上手快、中文生态好 | 复杂交互场景组件不如 AntD 丰富 | — |
| 自研组件库 | 完全可控 | 成本极高，违背非目标（不自研基础设施） | 排除 |
| Next.js / Nuxt SSR | 利于 SEO | 后台不需要 SSR，增加部署复杂度 | 与「纯静态托管」要求冲突 |

## 后果

**正面**：Element Plus 的表格/表单能力可直接支撑 `<CrudTable>`；按需引入后体积可控（gzip ≤ 500KB）；生成器产出的页面可直接复用组件。

**负面 / 代价**：Vue 与 React 双模板会带来长期维护成本；Element Plus 深度定制需覆盖样式变量。

**缓解措施**：把前端与后端的耦合面收敛到「权限码 + 菜单树 + 统一响应/错误码」三层契约，使第二模板只需实现契约；构建体积纳入 CI 门禁。

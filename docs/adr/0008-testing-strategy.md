# ADR-0008 · 测试策略：SQLite 单测 + 双库集成矩阵

- 状态：已采纳
- 日期：2026-10-09
- 关联：[PRD-002](./../prd/prd-002-database-abstraction.md)、[测试用例](../50-test-cases.md)、[ADR-0007](./0007-database-switchability.md)

## 背景

1. 开发者本地反馈要快（秒级），但方言差异必须在真实数据库上验证。
2. 全部用容器数据库跑测试会让本地开发体验变差，进而导致「不跑测试」。
3. 需要明确各层测试的比例与工具，避免用例结构失控。

## 决策

- **单元测试**：用 SQLite（文件或内存），覆盖纯逻辑、装饰器、适配器逻辑（fake 实现），目标执行 ≤ 60s，占约 70%。
- **集成测试**：用 Testcontainers 起真实 MySQL 8 与 PostgreSQL 15 并行执行，覆盖接口 + 真实依赖，占约 25%。
- **端到端**：Playwright 只保留后台黄金路径（登录 → 权限 → CRUD → 审计），≤ 5 条，占约 5%。
- 测试数据由工厂函数生成，用例间以事务回滚或独立 schema 隔离。

## 备选方案

| 方案 | 优点 | 缺点 | 未选原因 |
|---|---|---|---|
| 全部用容器数据库 | 与生产一致 | 本地反馈慢，开发体验差 | 会被绕过 |
| 全部用 SQLite | 最快 | 方言差异测不出来，切换承诺失效 | 与 ADR-0007 冲突 |
| 全部 mock 数据库 | 极快 | 测不到真实约束、事务与索引行为 | 只能用于单测层 |
| 分层：SQLite 单测 + 双库集成 | 兼顾速度与真实性 | 需维护两套数据与工厂 | — |

## 后果

**正面**：本地开发秒级反馈，关键差异由 CI 兜底；测试金字塔结构清晰，易守覆盖率门禁（整体 ≥ 70%，auth/cache/orm ≥ 85%）。

**负面 / 代价**：需维护可在三种数据库上跑通的测试数据工厂；CI 资源消耗更高。

**缓解措施**：工厂函数统一封装差异（如时间精度、布尔表示）；集成测试并行化；每日流水线跑全矩阵，PR 只跑受影响包 + 核心矩阵。

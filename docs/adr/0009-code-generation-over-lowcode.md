# ADR-0009 · 快速开发靠代码生成，不做低代码引擎

- 状态：已采纳
- 日期：2026-10-09
- 关联：PRD-006、[愿景与范围 NG4](../00-vision-scope.md)

## 背景

1. 「一个 CRUD 模块 ≤ 10 分钟」是核心目标（G4），实现方式有两条路：运行时低代码引擎，或代码生成器。
2. 低代码引擎（元数据驱动渲染）在简单场景极快，但复杂逻辑会撞墙，且把业务锁死在平台内。
3. 本框架的定位是「给开发者的框架」，产出必须可读、可改、可走 Git 评审。

## 决策

采用**代码生成器**：由数据模型生成后端模块、前端页面、菜单与权限点 seed，产出的是普通源码。

关键约束：

- 默认不覆盖已存在文件，重跑需 `--force`；提供 `--dry` 预览 diff。
- 生成代码与业务代码分离（生成 `*.base.*`，业务继承/扩展），避免重生成覆盖业务逻辑。
- 生成结果必须通过 lint 与编译，否则回滚本次写入，不留半成品。
- 模板可覆盖（项目级 `templates/codegen/`），全团队统一产出风格。

## 备选方案

| 方案 | 优点 | 缺点 | 未选原因 |
|---|---|---|---|
| 低代码引擎（元数据 + 运行时渲染） | 改字段即时生效，不用重新部署 | 复杂逻辑绕不过去；业务被平台锁定；调试困难 | 违背非目标 NG4 |
| 代码生成器 | 产出可读可改源码，无运行时锁定；可走 Code Review | 模型变更需重跑生成；需处理覆盖冲突 | — |
| 两者都做 | 覆盖全场景 | 维护两套体系，成本翻倍 | 首版不做 |

## 后果

**正面**：生成物即普通代码，可评审、可调试、可脱离框架演进；模板可定制，统一团队风格。

**负面 / 代价**：模型变更后需重新生成并合并；生成器自身是长期维护资产。

**缓解措施**：`--dry` + 非强制覆盖 + `*.base.*` 分离 + 生成文件头部标注 `@generated`；生成器自身单测覆盖率 ≥ 80%。
